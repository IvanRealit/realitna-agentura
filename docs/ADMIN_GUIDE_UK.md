# Робота персоналу

Вхід: `/admin`, лише власний обліковий запис. Створення початкового адміністратора описано у README; пароль не зберігати в Git або документах. Немає публічної реєстрації. Seed додає DEMO-контент, не запускайте його на production як спосіб імпорту справжніх даних.

1. У Properties створіть DRAFT: slug, SK заголовок/опис, місто/регіон, ціну, характеристики і фото. Для першої публікації потрібні додатна ціна, фото та SK опис щонайменше 40 символів.
2. Agent заповнює власне оголошення й переводить у REVIEW. Manager/Admin перевіряє і переводить у PUBLISHED. Agent не публікує та не редагує вже опубліковане.
3. Якщо інший працівник змінив запис, сервер повертає VERSION_CONFLICT. Не перезаписуйте чужі зміни: збережіть свій текст окремо, перечитайте запис і узгодьте зміни. Видалення також потребує актуальної version.
4. Leads містить справжні збережені запити з сайту; змінюйте NEW/IN_PROGRESS/CLOSED, відповідального і нотатки відповідно до прав. Це ще не Client/Deal CRM.
5. Content редагує наявний контент/SEO; Settings — бренд/контакти/retention; Users — ролі та active; Audit — важливі зміни. Докладні права: `security/PERMISSION_MATRIX.md`.

На мобільному є нижня навігація dashboard/properties/leads; форми адаптуються до вузького екрана. Фізичний iPhone/камера/HEIC ще не перевірені. Немає безпечного offline cache персональних даних. Використовуйте вихід з облікового запису на спільних пристроях.

Немає екранів Finance, AML, Documents, Calendar або Backups; не вважайте їх прихованими готовими модулями. Не видаляйте дані для GDPR без перевірки правових строків і legal hold; чинний purge простий та потребує перегляду до production.
